# Truman的十大AI任务（上半场：任务1-5）

> 揭秘直播（案例开放麦，非正课）：Truman 以「AI实践者」而非 CEO 身份，解读一堂官方挑战「十大AI任务」中相对简单的任务1-5，讲自己这一年的实操案例。**官方做任务书的初衷是"演习场"**——很多同学迟迟没做 Partner、没做 Skill、VibeCoding 一直没"感受过第一次的爽"，基本功差距越拉越大且缺少共识框架；于是在模拟环境里给一组基本功练习，相互切磋、正向建立能力，不用去真实战场试错、流血、焦虑尴尬。分两个层级：**基础版**（全体会员，用来"进入状态"）与**挑战版**（高手营挑战）。全场最重要的三个字：**回不去**——每个任务入门的标志，就是习惯了它之后再退回旧工作方式会感觉效率大大下滑，"大概率就是这个任务把你击穿了"。

## 任务1：场景梳理

**缺少场景，是缺少AI落地的根本原因。** 很多人觉得"VibeCoding 跟我无关、AI落地场景很少"，本质是场景清单没拉开。三个维度（对应 [[yitang-scene-star-model]] 的三套文档）：

1. **从业务出发**：某一个业务、大场景的具体展开；
2. **从能力出发**：从某一个 AI 基本功/基础设施出发；
3. **从未来出发**：跳出现实，从未来美好的想象出发。

### 案例：系统学习工作台

十一假期闭关学工作台，教程太乱 → 先建立基本常识、总结自己的框架 → **逼自己灵感闪现 30-50 个工作台场景** → 基于 [[deepseek-harness|DeepSeek Harness]] 设计三层解耦：

| 层 | 职责 |
| --- | --- |
| Dock 插件 | 工作台基础设施：应用台、自启动、自动任务、Agent 桥接 |
| 元 WorkSpace | 未来可简单配置出各种工作台的基础设施 |
| 工作台数据 | 具体工作台的里程碑工作流、技能、评估、工具 |

Truman 判断：DSH 很可能是未来 2B 公司落地的 Harness 基础设施。

### 两个提醒

- **灵感闪现文档是人写的**，AI 最多辅助提议，全权交给 AI 就没意义了（一次性把思路打开，即便不执行也不乱）。
- 实在不会/没时间，可以让 AI 帮跑一轮：OneLifeTree（Y模型+本体+巡查建模+内核边界）案例中让 AI 巡查 5 分钟解放思想——质量参差、印象不深，**但比一个人头脑空空要好得多**。

## 任务2：搓Partner

**Partner = 基于 LLM 直接对话的系统提示词封装。**
优点：简单、快、省 Token、容易进入心流；缺点：缺少工具、缺少动手、没有 Agent 循环。适合短平快、快问快答的任务（方法论详见 [[yitang-partner-encapsulation]]）。

### 案例：磨课搭子的三年演进（本任务最有教学价值的案例）

| 阶段 | 做法 | 结果 |
| --- | --- | --- |
| 2024-2025 | Gemini 直接聊，每次开窗口评审做课逐字稿 | 有对话伙伴，但**非常不稳定，ROI 很低** |
| 2026.3 | 封装完整 Agent 研究团队 | 上下文完整、有记忆，但**非常慢、多 Agent 协同很糟糕** |
| 2026.4 | "角度清奇"的提示词封装 YAI：「我的课件丢了，只剩支离破碎的文稿，帮我还原和评估」 | **20min 封装"课程展开专家"**，教研团队主动称赞 |

规律：豪华 ≠ 好用；一个精心打磨的角色提示词，胜过一个不稳定的 Agent 团队。

### 其他案例

- **技术顾问**：春节前后两个月聊了将近 50 个 Session，至今遇到教程类问题仍然习惯性找它。
- **高频 Partner**：把若干课题组合成完整、层次清晰、**RAG 友好的数据包**（六七百字提示词）——手工拉取或让 CLI 自动来取，全面增加工作的质量和确定性。
- **顶级代笔**：第一阶段发几篇最好的文章（如即刻"千赞"小文章）训练提炼**写作 DNA** → 熟悉自己的写作基因 → 发任务测试 → AI 咔咔干活。朋友圈/小红书策略 Partner 同思路。
- **挑战：里程碑辅导流程**——分布推理专业提示词的练习题；"爆炸式调研" Partner 的 MVP 就是 30min 搓出来的。

**结论**：Agent（含一堂 CLI）的确更强，但日常 **20-30% 的任务**是和 YAI / DeepSeek 官网直接聊——快问快答、快聊快结束；小任务让 Agent 转几分钟，太拖沓。

## 任务3：封装Skill

Truman 的观察（baolun）：**从业务现场封装的技能 90% 都很好用；市场上平均水平的公开技能 99% 都很难用**——边界不清晰、过度营销、工程化弱、质量不合格，是系统性问题。

### 案例：DeepDebug（深度调试）

龙虾 IM 长连接算法 Bug 改一晚持续崩溃（1→2→3→1 的"转圈Bug"），差点删库。转折：**给 AI 上课**——讲什么是假设思维、全局最优解、关键假设、加法减法验证，然后让 AI 带着假设思维解题：全面巡查提假设 → 找关键假设 → 回归历史 Bug（只调研不动手）→ 充分验证后直接 MVP。**折腾三四个小时的问题 10 分钟解决**，趁热封装成 DeepDebug 技能；半年又解决 30+ 疑难杂症——"把一个不科学的直觉黑盒，变成相对科学推理的白盒；一次成功的经验，变成我所有 Agent 的高阶技能。"

### 案例：全量复盘（经验资产化）

设计稿改 5-30 轮的过程全在 Session 对话框里不可见——**这是最宝贵的资产**。提炼"全量复盘"技能后，只需说一句话，AI 10 分钟写出一两万字的全量复盘资产文档（如堂三角完整设计过程：拿到文档就能二次设计或复刻）。同族：DesignTaste（吃进审美规范）、BetterGraph（架构图）、GPT-Image（设备×免费额度排序）、BetterFork（检索相关 Session 压缩上下文，在新 Session 续工作）。**但凡高频高质量、需要反复口喷的工作，都值得封装成技能。**

### 案例：Better-Skill（工程技能的技能）——五步法

针对"封了很多、质量贼随机"的痛点，半年前做《高阶 Skill 指南》的过程本身就是方法论：

1. **快速认识**：问 AI 要开源且验证过的教程；最佳案例是 Claude 官方 skill-creator 元技能；
2. **AI 翻译和解读**：Trae 翻译 + Antigravity 解读精华，双开交叉工作——**不是语言翻译，而是保持"执行 100% 有效"的翻译，本质用的是 AI 编程工具**；
3. **自建最佳实践教程**：让 AI 合并所有官方教程精华写一篇 Top-down 实操教程。技巧：**基于原始案例建模，显著差于先做一次萃取、再二次合并萃取**；
4. **逐步打磨**：重点模块挨个解读交叉验证，MECE、排优先级、加参考案例、补底层逻辑——每个环节提 2-5 轮"不够好"；
5. **交叉验证**：并入手里其他教程（Claude 官方培训 + 同学分享），让 AI 交叉测评、打分、吸收，最后合并。

### 技能复利

- 过去 7 天提炼（升级）17 个技能，**S 级约占 1/3**（资产级、反复调用、不舍得分享）；
- 专门做了「技能中心」工作台管理和排序，**7 台电脑/服务器 × 多 Agent（Codex、Hermes、dsh、ClaudeCode）共享同一套技能**；
- 技能像"苦练基本功"，是长期复利模型——一个像 AI，一个面对人。

## 任务4：梳理双三角

双三角（[[yitang-dual-triangle]]）是搓 Partner 的基本框架（ROI C partner、清单体笔记 P partner、一堂选课助手），也是做短平快 AI MVP 项目的基本前提（给 360 中高层做内训，升级 AI 训练计划最重要的准备工作就是梳理双三角）。**三个阶段**：

1. **很有道理**：学了模型，觉得好有道理——停在认知；
2. **动手实操**：遇到具体 AI 问题拉满填双三角，工作体系和信心有巨大提升（案例：《3小时挑战手搓百万短视频访谈操盘手》最重要的一步就是填写一遍双三角画布，用 A3 纸自由填写讨论）；
3. **肌肉记忆**：认真填过 **10-20 个**之后，方法论融入决策习惯，条件反射地看出"这缺审美、这缺数据"——此后反而"不必一定填"。

高手营要努力找机会练拆解：公司细分场景 AI 落地 / 搓 AI 分身助理 / 做好看又难做的海报 PPT / 做大概率会失败的 AI 交付。**拉满完成 1-3 次，基本就完全回不去了。**

## 任务5：建立AI知识库 & 上下文微操

### 范式转变：Obsidian 是给 AI 用的

Truman 曾一直怀疑鼓吹 Obsidian 是"除非必要勿增实体"，直到某天深夜被一句话击穿：**Obsidian 就没打算让人用、让人写、让人协作——就是给 AI 用的**。这不是工具升级，而是工作范式升级：**把 Agent 当员工，把 Obsidian 当协作知识库**，全面分工协作。

核心原则：**减少"传纸条模式"，尽早进入"共享上下文"模式**——降低对 Session 的依赖，增加资产化文档的建设，最终追求上下文全部打通（对照 [[adapted-6plus1-rss-obsidian-kb]]、[[cross-app-ai-knowledge-base]]、[[obsidian-multi-agent-consensus]]）。

### 上下文微操（本场最具原创性的方法）

三个问题推导：①项目拆解推进的经典结构 = **里程碑模型**；②决定 AI 质量最重要的可控因素 = **上下文**；③复杂难任务的最简策略 = **拆解**。三词合一，Truman 造了一个新词：**上下文微操**。

> 刻意练习一套**以文档为驱动、以严格编号为顺序、以清单体笔记为逻辑**的工作框架，来精准管理 AI 一步步推理和工作，全面提升 AI 解决复杂项目的质量上限。

**编号文档树实例**（搓一个正式 Partner 项目的执行过程）：

```
00 顶层文档（口喷，读双三角）
├─ 01 完整口喷所有美好想象
├─ 11 画像 / 12 原则（派 2 个 Agent 分头研究）→ 合并为 10 综合画像顶层建模
├─ 20-25 数据包（多 Agent 研究）→ …
├─ 31 历史参考 / 32 我的想象（AI 收集资料）→ 合并为 30 正式教学工作流
├─ 41-46 逐个打磨 → 合并为 40
└─ 00/10/20/30/40/50 最终合并 → 70.Partner提示词
   └─ 90 全量复盘沉淀执行细节
```

即：一步步带着 AI 在具体环节上，**精准配置 1、2、3、4 作为上下文推导出 5；再精准配置 3、5、6 推导出 8**——每一步都按逻辑推导和评估。

**四个关键词**：

| 关键词 | 含义 |
| --- | --- |
| 文档为驱动 | 全程不看 Agent，全程只看和评审文档 |
| 严格编号为顺序 | 00/10/20 有总分和推理逻辑，1xx 合并为 10、2xx 合并为 20 |
| 清单体笔记为逻辑 | 准确凝练起名（最好 `xx：xxx`），支持扫读，百万字上下文一套人脑可管理 |
| 刻意练习 | 相信刻意练习的人，这是巨大的同行竞争力 |

**里程碑级微操节奏**：里程碑**之间**有依赖关系——谨慎、争取串行、不跳步、避免回退；里程碑**内部**无依赖——尽量拉满多线程×多口喷并行，省时间。

### 进一步的展望

- **原生知识管理工具**假设：更原生适配多 Agent 角色协作的 Obsidian，人类减少复制粘贴当胶水，AI 自动分配、自动路由、自动整理，最终摆脱人类的自托管；
- **WriteLess Pro Max**（放进 DSH 工作台）：完全以 Agent 为中心的自动化文档管理——"我们是 Leader，下属写的文档，我可以提建议、可以推翻，但我不动手自己改一个字"；
- **Better-Notes**：最难的是命名和清单体——深夜突发奇想"带人不好学，我来教 AI"：给方法（清单体/里程碑/建模的课）→ 给模型（一口气把经验喷出去）→ 做调研（全量巡查大几十个项目总结规律）→ 提假设（10 几轮反馈迭代）。OneLifeTree 最难最复杂的项目，**一半文档是 Agent 自动做的**；
- 技能全家桶待开源验证后送出：Better-Graph（架构图）、BetterPK（科学实验）、BetterWord（优雅文案）、Feishu2Slide（PPT）、BetterActor（一致性）、BetterDirector（AI演技）、BetterNote（笔记目录）、BetterFeedback（打分循环）、MagicDock（工作台基础设施）。

## One More Thing：Trumind《回不去》

送给同学的礼物——"原版·体育场摇滚"《回不去》，歌词本身就是十大任务的通关叙事：第一关拆场景（"我把十年的活，拆成五十条"）→ 第二关搓 Partner（"我给它起了名字，一喊它就来"）→ 第三关封 Skill（"我一个词，它就能开工"）→ 第四关双三角 → 第五关建库 → 第六关助理 → 第七关分身 → 第八关 VibeCoding → 第九关工作台 → 第十关网站。点题句：

> AI 我以为是一堵墙 / 原来是一座天梯 / 爬上去了 / 就再也 回不去

## 一句话总结

> 十大任务是"AI 基本功没有短板"的必经之路，入门的唯一标志是**回不去**；而把五项基本功串成体系的那根线，是**上下文微操**——文档为驱动、严格编号、清单体逻辑、里程碑串行内部并行，让 Obsidian 从笔记工具变成多 Agent 项目的推理管理操作系统。
