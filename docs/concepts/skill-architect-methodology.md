# Skill 架构师方法论（一堂·贾老师/子莫先生）

> 一堂专家分享（贾老师/子莫先生）：写不好 Skill 的根源是**把 Skill 当成"提示词模板"（写知识而非程序）**。方法论来自飞叔对花叔前端设计 Skill 的拆解——好 Skill 本质是可执行程序（输入/输出/检查点/异常处理/优先级规则）。核心武器：**五层架构模型**（触发/角色/原则/流程/资源）+ **7 步创建法则** + **100 分审查制**。一句话：**Skill 架构师不是帮你"写一个 Skill"，而是帮你"建造一套让 AI 无法做错的工作系统"。**

## 核心诊断：知识 vs 程序

> 大多数人写 Skill 是把脑子里的东西写下来扔给 AI——写的是知识不是程序。结果 AI 时而靠谱时而跑偏，同一 Skill 不同对话表现天差地别。

花叔的 Skill 强，因为本质是可执行程序（有输入/输出/检查点/异常处理/优先级规则），不是"告诉 AI 做什么"，而是**"构建一个让 AI 无法做错的系统"**。

> 💡 与 [[diary-to-book-skill]] 完全同构：姬恒从执行 AI 视角发现"规则必须变成中断点不是注意事项"，贾老师从架构师视角提出"程序而非知识"。

## 五层架构模型

```
Layer 5: 触发层 (Trigger)    → 什么时候加载？穷举所有说法 + 明确不适用场景
Layer 4: 角色层 (Persona)    → 具体职业身份 + 与用户关系 + 能力边界
Layer 3: 原则层 (Principles) → 不可违反规则（编号/优先级/触发条件/反例）
Layer 2: 流程层 (Workflow)   → 输入→动作→输出→检查点 + 异常处理表
Layer 1: 资源层 (Assets)     → assets/ references/ scripts/ 知识库和工具包
```

**各层要点**：
- **触发层**：穷举所有可能说法（口语化/简称/错字）；明确不适用场景——试图包揽一切的 Skill 等于什么都没做
- **角色层**："你是助手"是最糟身份（泛化身份→泛化工作）。公式：具体职业身份 + 关系 + 能力边界
- **原则层**：**每条原则必须有反例**。没反例是空话。原则冲突时编号小的优先（模棱两可时的裁决规则）
- **流程层**：每步骤切"输入→动作→输出→检查点"四环节，关键步骤后强制暂停；预设异常处理表（模糊/改主意/超范围）
- **资源层**：模板/组件/脚本/参考文档沉淀到目录，Skill 是知识库 + 工具包

> 💡 **反例为何有效**：没反例 AI 读到"注意一下"，有反例 AI 读到"上次翻车了不能重蹈覆辙"。反例是原则的锚点，把抽象警示变具体教训——这是把隐性经验显性化的关键。

## 两种工作模式

### 审查模式（打分 + 诊断）
读取标准文档 + SKILL.md → 逐层审查每层打分（总分 100）→ 输出审查报告（评分+问题定位+修改方案）→ **必须等确认才动手改（铁律，防 AI 越权）**

### 创建模式（7 步法则）
1. 确认领域边界（解决什么/不解决什么）→ 2. 定义角色 → 3. 提炼原则（每条配反例）→ 4. 设计流程（输入/输出/检查点）→ 5. 预设异常（模糊/不足/超范围/不满意）→ 6. 整理资源 → 7. 穷举触发词。每步有检查点等确认才进下一步。

## 为什么有效（四条底层原因）

1. **解决 AI"默认值"问题**：训练语料决定默认输出是"最大公约数"（安全平庸）。花叔写"不要做什么"比"要做什么"还多，强制反例和边界针对此
2. **把经验变成可执行规则**：反例是锚点，抽象警示变具体教训
3. **引入检查点机制**：线性 Skill 跑偏用户重来；检查点让用户中途介入，避免"干完发现全白干"
4. **量化标准非主观**：100 分制 + 五层逐项打分，质量可追踪可对比
