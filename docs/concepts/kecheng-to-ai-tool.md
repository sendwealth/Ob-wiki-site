> 把课程方法论通过真实业务实践，沉淀成可复用的 AI 工作流（PRD/SOP/Skill），实现从"学完一门课"到"变成自己的能力系统"。

# 把课程变成 AI 工具

## 核心方法：五步闭环

1. **做作业不写感想**：让 AI 反思而非总结——最有用的方法？做得好的？明显问题？下一步怎么练？
2. **真实业务练**：不用假题目，用有真实付费判断、真实转化压力的问题
3. **三轮质检**：① 有证据吗？② 有更新的数据吗？③ 有更贴本地/中小微的数据吗？
4. **调研变作业**：课题→设计→事实→证据→动机→定价→优先级→验证计划→复盘
5. **沉淀成工具**：PRD / SOP / 模板 / [[oscar-research-methodology|Skill]]

## 关键原则

- **顺不等于对**：AI 写得再顺，缺证据就是推理，不是结论
- **垃圾进垃圾出**：给 AI 的资料要结构化 Markdown，去除噪音
- **持续纠偏**：目标定义→提供约束→识别假结论→补证据→纠偏，不是一次提问拿答案
- **拒绝能力**：好的 AI Skill 不是永远鼓励上 AI，而是能判断该不该用、该用什么

## 从课程到 Skill 的 9 阶段 SOP

| 阶段 | 产出 |
|------|------|
| 1. Go/No-Go | 是否值得做 + 定位 + 用户 |
| 2. 整理主线 | 结构化课程主文档 |
| 3. 抽案例 | 案例库 + 高风险清单 |
| 4. 诊断协议 | 流程 + 评分 + 风险分级 |
| 5. 证据校准 | 主张审计 + 真实案例 + 不当复读机 |
| 6. 工程结构 | SKILL.md + references/ |
| 7. 测试评审 | 正例 + 反例 + 独立评审 |
| 8. 对比测试 | Skill vs 裸模型（12 维度） |
| 9. 维护迭代 | 版本规则 + 回归测试 |

### 对比测试结果（关键发现）

- Skill（36/36）vs 裸模型（8-9/36）
- **最大差距**：拒绝能力——Skill 能说"暂缓不做"，裸模型对一切都同意
- **最危险场景**：裸模型同意无合规框架下构建保险 AI 销售，并随意承诺转化率提升

## 复用模板

学完任何课程后：
1. 不问"帮我总结"，问反思性问题
2. 找真实业务问题练
3. 对 AI 答案做三轮质检
4. 让 AI 沉淀成工具（PRD/SOP/Skill）
5. 输出可复用资产
