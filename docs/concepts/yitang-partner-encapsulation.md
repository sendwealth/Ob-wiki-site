# 封装一个 Partner（系统提示词）：六阶段方法论

> 一堂 2026 AI 大航海官方任务包02，任务包01（[[yitang-skill-encapsulation]]）的姊妹篇。01 封装的是**技能**（把一个重复动作做好），02 封装的是**伙伴**（把角色、方法、资料和判断标准封装进一个可反复召唤的 AI Partner）。核心命题：**封装，就是把过去的经验抽离出来，变成未来可复用的能力——先把一次对话做成有效解法，再把有效解法固化**。与 Skill 的关键差别：Partner 有明确角色、能主动引导你、有固定入口，"知道服务谁、怎么与你配合、按什么标准做事"。点睛之笔：当你把一次好对话，沉淀成一个清晰场景、一套有效解法和一个随时找得到的入口，AI 就开始真正用上你的经验。

## 三要素框架

| 要素 | 要回答的问题 | 留下什么 |
| --- | --- | --- |
| 🎯 场景 | 谁在什么节点，会反复遇到什么问题？ | 一个细分场景和清晰边界 |
| 🧠 解法 | 凭什么把它做好？需要什么方法、数据和标准？ | 系统提示词＋必要数据包＋处理流程 |
| 📍 触点 | 下次从哪里找到、如何直接调用？ | YAI 自建 Partner，或工具的固定系统指令入口 |

## TCPR 角色分类

选题前先问"这个问题该找谁"——Partner 首先是一个**角色**：

| 角色 | 协作方式 | 典型场景 |
| --- | --- | --- |
| **T**｜教学型 | 教会你、训练你、提升能力 | 概念讲解、入职训练、学习教练 |
| **C**｜咨询型 | 与你讨论、判断、推演方案 | ROI 决策、职业探索、方案诊断 |
| **P**｜实践型 | 接收材料，直接产出结果 | 周报整理、文案清洗、大纲生成 |
| **R**｜研究型 | 调研、建模、研究规律、结构化知识 | 竞品定位、行业研究、资料结构化 |

一个 Partner 可以有组合能力，但**先写清主要角色**：它到底是在教你、陪你判断、帮你干活，还是帮你研究？

## 六阶段方法论

```
① 明确场景与角色边界 → ② 草稿版双三角(5min预判) → ③ 充分准备打磨(加法)
→ ④ 充分版双三角(排序) → ⑤ 跑通一次，封装 V1 → ⑥ 固定入口，换任务调用复盘
```

### ① 明确场景，设定角色和边界

- 先发散 3—10 个想法（注明频率 / TCPR / 价值），再按频率、价值、材料可得性、质量可判断性做减法。
- **优先把完整工作流中最有价值的一小段做好**（例：不做"PPT 助理"，先做"PPT 内核打磨助手"）。
- **身份卡**：正式名称、TCPR 定位、目标用户、细分场景、内核（主要解决什么）、边界（主动砍掉什么）、交付物与 3 条合格标准。
- 一句话定义公式：当【谁】遇到【具体问题】时，Partner 作为【角色】，使用【输入与方法】，帮助得到【可验收结果】。

### ② 草稿版双三角（5 分钟预判）

用 [[yitang-dual-triangle|双三角]] 六个角（审美 / 体系 / 创造力 / 场景 / 数据 / 基本功）按直觉和经验快速填 3—10 个关键词——**先不追求完美，先把能想到的写下来**。

### ③ 充分准备和打磨（提假设 / 拉单子）

"**充分做加法，专业做减法**"：先全写下来，再排序取每个模块的最高优先级。要素从 3-10 个扩到 10-30 个，围绕三个打磨角度：

1. **提升审美**：更高水平交付的审美标准是什么？有哪些高手标杆案例？可复用的流程模型框架？新假设新切入点？
2. **找数据包**：必备数据源 / 可选数据包 / 需要补充的案例样本 / 需要调用的 AI 能力与工具特性——数据如何提升交付质量？
3. **梳理里程碑**：把场景推进成可执行里程碑（先做什么后做什么）、关键验证点、最大风险与应对。

### ④ 充分版双三角（充分加法，理性排序）

六个角各排 **Top 3**，标出最重要的审美 / 数据 / 基本功，选出**最值得优先执行的 5 件事**，评估信心提升与可行性。进入第五阶段前收敛出首轮要素清单：聚焦场景、保留的 3—5 个关键要素、资料入口、里程碑（每步有产物）、2—3 条可检查验收标准、**最先验证的一个关键假设**。

### ⑤ 跑通一次，把有效解法封装成 V1

带着筛选出的要素完成一次具体任务，边做边对照里程碑和验收标准，**记录哪些准备真正起作用**。任务结束后只把**已验证有效**的规则写进 V1 系统提示词。V1 五要素：

1. 角色、服务场景、内核边界和交付结果；
2. 必需资料、每次使用时要补充的输入；
3. 已验证有效的步骤、阶段产物、**确认节点**和质量标准；
4. 缺信息、事实冲突和越界请求的处理方式；
5. 固定输出格式与一条调用示例。

纪律：只固化确认有效的做法，待验证想法单独列出；不把本次任务的人名、数字、临时要求写成通用规则。

### ⑥ 固定入口，换任务再调用并复盘

- 把 V1 保存到**固定入口**（YAI：召唤 Partner → 创建自有 Partner → 粘贴系统提示词 → 配置资料 → 保存；或其他工具的自定义助手）。
- **新对话 + 换一份同类材料**再调用，看它能否**离开原对话独立工作**；发现问题就改一处、再试一次（V1→V2）。
- 复盘哪些双三角要素真正有用（保留 3 个 / 删掉什么 / 下一步），并做 Before→After 对比（草稿版双三角 vs 充分版）。

## 与任务包01 的对照

| 维度 | 任务包01 Skill | 任务包02 Partner |
| --- | --- | --- |
| 封装对象 | 一个重复动作的方法 | 一个角色的完整协作方式 |
| 载体 | Skill 文件 / 标准指令 | 系统提示词 + 数据包 + 固定入口 |
| 准备框架 | 六类规则（场景/输入/步骤/标准/边界/输出） | 双三角六角 + TCPR 角色 |
| 流程 | 五阶段，直接提炼规则 | 六阶段，双三角准备先行再跑通 |
| 验证 | 三类测试（正常/缺信息/边界） | 同三类测试 + 同学接力试用 |
| 诚实标准 | 不把「生成提示词」当完成 | 没有新任务调用要标「待复用验证」 |

共享的底层纪律：经验必须来自**真实跑过一次并被纠正过**的过程（V0 → 有效规则），只固化验证过的东西，异常处理（缺信息 / 冲突 / 越界）是必备件，三类测试是验收底线。

## 案例库精华

- **给 Partner 设计反驳和追问机制**，减少只肯定方案的问题（2026 商业突破大航海第3周精选）。
- 冉鹏·记忆胶囊：在 GPTs 用"JSON 行为宪章 + 动态 JSON 步骤 + 结构化报告"，**把固定行为规则与会话状态分开，避免长聊后忘记流程**。
- 李守彬·灵感闪现助手：**先做纯提示词 Partner，再按实际卡点增加流程**（对应任务包"不必第一版就把所有功能装满"）。
- 莉·新闻稿品控：把质量标准写清楚，用**评分**检验 Partner。
- Val：先做简单提示词，再用输出反馈**逐轮修改**。

## 一句话总结

> Partner 封装 = **选定一个角色（TCPR）和它的边界 → 用双三角充分准备（加法再减法）→ 跑通一次只固化有效规则 → 装进固定入口换材料再调用**。技能解决"这件事怎么做对"，伙伴解决"这类事谁来陪我做"。
