# 封装第一个「非常好用」的 Skill：五阶段方法论

> 一堂 2026 AI 大航海官方任务包01。核心命题：**经验不只存在脑子里，也可以成为 AI 的能力**。把一件每周都要向 AI 重新解释一遍要求的小事，先做好一次，再把方法留下来，变成下次能直接调用的 Skill——这是 OPT 一人团队积累能力资产的第一步。大白话只做三件事：**① 找一件值得反复做的事 → ② 做好一遍，把方法写下来 → ③ 换份材料再用一次**。点睛之笔：**封装 Skill 本质上不是把提示词写长，而是把判断讲清**。

## 五阶段方法论

```
① 明确场景与目标 → ② 先把一次任务做好(V0) → ③ 把经验提炼成六类规则
→ ④ 封装成能调用的 Skill(V1) → ⑤ 换份材料验证，形成自己的结论(V2)
```

### ① 明确场景与目标

- **场景清单**：列 3—5 个「名称 / 频率 / 麻烦点」，先看见自己的重复工作。
- **选题四判据**：重复频率、实际价值、材料是否够用、能否判断好坏。**只用一两次的任务，不必为了封装而封装**。
- **缩小范围**：说清使用者、触发场景、这次只做什么、暂时不做什么。
- **合格标准**：写下 3 条可逐项核对的标准（例：不把建议写成已决定；不编造负责人和日期；每条行动项能回到原文）。
- **一句话目标公式**：当【谁】遇到【场景】时，使用【输入】，按【方法】，产出【结果】。

练习路径二选一：**真实业务实践（推荐）**——近期还会做、有原材料、能判断好坏；**模拟案例练习**——用官方案例（会议行动项整理 / 学习笔记整理）跑通流程，标注「模拟练习」，之后必须带真实材料验证。

### ② 先把一次任务做好（V0）

带上原材料，和 AI 一起做出一份**你认可**的结果，把纠正过程留下来：

- 记录 **AI 第一版哪里不对**（原话 + 你的纠正，写具体）；
- 记录 **改到什么程度才愿意用**（认可的输出即 V0）；
- 沉淀 **下次还会用到的提醒**（例：不把建议当决定；未指定负责人就不补名字；相对日期没有参照时保留原文并注明待确认）。

> 完成标志：**你能对照原材料解释为什么它合格，而不只是觉得它「看起来不错」**。V0 是这次任务做好的结果，还不是 Skill。

### ③ 把经验提炼成六类规则

把「靠你提醒才做对的地方」变成下一次也能执行的做法——AI 提炼只是初稿，必须逐条确认：

| 规则 | 关键问题 | 示例（会议行动项） |
| --- | --- | --- |
| ① 场景 | 什么时候用 / 不用 | 用于从会议记录提取行动项；不用于替团队制定决策 |
| ② 输入 | 必需什么，缺了怎么办 | 必需会议记录；"周五"转日期需会议日期；读不到原文先请用户补充 |
| ③ 步骤 | 做法拆成哪些动作 | 找候选 → 区分决定/建议/待确认 → 提责任人和时间 → 回查原文 → 按模板输出 |
| ④ 标准 | 怎么判断做得好（含正反例） | 正例："建议下周试试"进入建议区；反例：写成已分配任务 |
| ⑤ 边界 | 缺信息 / 冲突 / 超范围怎么办 | 缺负责人写待确认；日期冲突列出请用户确认；无记录不猜决策 |
| ⑥ 输出 | 固定交付什么 | 行动清单（事项/负责人/截止/原文依据）+ 建议区 + 待确认区 |

提炼要求：每条规则注明来源（原材料 / 我的反馈 / AI 建议）；只保留能用于同类新任务的做法，**不把本次人名、日期写成固定规则**；没有依据的标注「待确认」。

### ④ 封装成能调用的 Skill（V1）

让规则**离开旧对话也能被完整读取和使用**。两种方式按工具选一：原生 Skill（按目标工具规范保存并加载）或完整标准指令（新对话粘贴全文）。V1 正文 = 六类规则 + 一条调用示例，**别人无需翻历史聊天就能开始**；较长正反例放 `references/`，固定输出模板放 `assets/`，不必为完整建空目录。

> 两个反直觉提醒：**保存了文件 ≠ 工具已经加载；只说技能名称 ≠ AI 能看到规则**。先确认正文与资料可读取，再进入验证。

### ⑤ 换份材料验证，形成自己的结论

**新建对话**重新调用（不口头补充整套方法），跑三类测试：

1. **正常任务**：换一份信息完整的新材料，看输出是否符合预期；
2. **信息不足**：删掉一项关键输入（如不给会议记录），看它是否先索要原文而不是编造；
3. **边界任务**：给一个相近但不适用的请求（如"替我们决定下周谁做什么"），看它是否说明超出范围。

发现问题 → **一次先改一类最影响使用的问题** → V1→V2 → 三重复测：原失败案例复测 + 正常案例回测 + 另一份新输入。**没有发现问题时保留 V1 并如实记录，不硬凑修改；没有实际运行的测试标注「待测试」，不编造通过结果**。

## 三个「完成」的诚实标准

- 能解释**为什么选这个场景**（而不是"AI 推荐的"）；
- 能讲清**自己的封装方法**（六类规则里哪些是自己补充/删除/改写的判断）；
- 在**新对话中用新材料调用成品**成功。

> 不把「生成了一段提示词」当作完成。

## 交付物清单

场景清单与选题理由 → V0 材料与认可结果 → 已确认的六类规则 → 可再次调用的 V1（Skill 文件或标准指令）→ 三类测试记录 → 实践结论与已知限制。

## 一句话总结

> 经验变成能力的路径：**选中一件值得重复的小事 → 亲手做好一次并留下纠正记录 → 把判断提炼成六类规则 → 封装成离开旧对话也能用的 V1 → 用三类测试在新对话里验证它**。判断讲得清，经验才留得下。
