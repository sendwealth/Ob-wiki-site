## 🧭 方向1：龙虾等AI工具使用问题

### 1.1 龙虾工作流控制与记忆管理

**【核心观点】** 根因是**显性化不足**——人脑里的判断逻辑没搬到配置里，模型只能猜。

**记忆三层策略**：

| 层级 | 方式 | 说明 |
|------|------|------|
| 短期 | 当前对话上下文 | AI 自动处理 |
| 中期 | MD 格式工作文档 | Obsidian/飞书，每次会话手动加载 |
| 长期 | 结构化配置文件 | Skill、System Prompt |

**实操**：
- **流程显性化**：SKILL.md 里把 trigger/skip 条件写死
- **避免自由发挥**：高风险步骤前强制 plan mode；CLAUDE.md 写「未确认前不修改关键文件」；反例存 feedback memory
- **记忆管理**：MEMORY.md 只做索引（≤150字/条），按 user/feedback/project/reference 四类拆独立 md
- **判断幻觉**：要求引用文件路径+行号；先 grep 验证再回答
- **单一龙虾边界**：走**专业方向**，养多只专业龙虾共享 skill 库
- **Windows 用户**：开 WSL2，别用 cmd

### 1.2 Skill全生命周期管理

**五步流水线**：发现 → 评估 → 改造 → 自创 → 协同

- 找 Skill：marketplace → plugin 仓库 → 一堂社群 → 自己写
- **先跑 3 次人工版**，记录输入/判断/输出，再用 `/init-skill` 转 SKILL.md
- **没跑过 3 次的工作流不要做成 skill——会僵化**
- 提示词→Skill：拆四块——触发条件/上下文/执行步骤/产出格式
- 多 Skill 协作：写 orchestrator skill 串联，不要塞一段长 prompt
- 推荐：Obsidian 存原始素材，龙虾 MEMORY.md 存指令性记忆

### 1.3 AI短视频工作流

**三段式**：脚本 → 素材 → 成片

- 脚本→ChatGPT/Claude/Kimi | 素材→Pexels/Pixabay | 视频→剪映/即梦/即创 | 发布→N8N/Coze
- 卖货短视频：CC + Skill 总控 + 即梦/可灵 + 剪映 API
- 自动上传视频号：playwright + cron 定时 + 保留 cookie
- 平台发布用 **N8N** 或 **Coze** 做调度层

### 1.4 多Agent协同与数字员工体系

**三要素**：分工 + 通信 + 总控

```
总控 Agent（Hermes/龙虾）
├── 专业 Agent 1（调研）
├── 专业 Agent 2（文案）
├── 专业 Agent 3（审核）
└── 执行 Agent（Claude Code/Codex）
```

- 数据映射：统一前缀（项目代号-日期-作者-内容.md）
- **中央集权比扁平群聊更稳定**
- 通信：Truman IM 首选；没有则用共享文件夹 + 文件名约定
- 长任务选 Hermes（自动重试+sub-agent），调试选 OpenClaw（透明）

### 1.5 ⭐ AI工具选择与对比

**先确定角色定位，再选一个工具深耕。**

| 工具 | 定位 | 适合人群 | 核心优势 |
|------|------|----------|----------|
| Claude Code | 代码执行层 | 程序员 | 深度代码理解 |
| Codex | 代码协作 | 开发者 | GitHub 深度集成 |
| OpenClaw（龙虾） | Agent 编排层 | 业务人员 | Skill 生态 |
| Hermes（马） | 智能体层 | 进阶用户 | 自演进能力 |
| Coze | 低代码平台 | 非技术用户 | 快速搭建 |
| Cursor | IDE 内嵌 | 开发者 | 实时补全 |
| N8N | 工作流自动化 | 进阶用户 | 节点丰富 |

**Coze vs 龙虾**：Coze 上手快、上限低；龙虾上手陡、上限高。**先 Coze 跑通，再上龙虾。**

**Codex ≠ Hermes**——Codex 强代码生成，Hermes 强 agent 编排，功能不重叠。

### 1.6 龙虾配置与跨工具集成

- OpenClaw→Hermes 迁移：拷 `~/.claude/` 整目录；云端 Gateway 推荐 Railway/Render
- 远程指挥 CC/Codex：云端龙虾通过 SSH/MCP 调本地 worker
- 龙虾搭 Dify 偏 Python：复杂工作流换 **N8N**
- Cron 定时：固定用 Claude/GPT-4，DeepSeek function call 兼容性弱
- **"贵的便宜"现象**：复杂任务用 Opus 一次到位反而省

### 1.7 Harness（ACP）权限控制

编辑 `~/.claude/settings.json`：allow 只读，deny 破坏性操作，ask 每次确认。

### 1.8 ⭐ 派兵布阵-工具三层架构

**核心**：能在 Chat 里 3 句话解决就别动 Cowork；能在 Cowork 搭工作流解决就别动 Code。

| 层级 | 国外工具 | 国内对位 | 用法 |
|------|----------|----------|------|
| Chat | ChatGPT, Claude | Kimi, 豆包, DeepSeek | 头脑风暴、随手问 |
| Cowork | Claude Projects, Notion AI | ColaOS, Hermes Agent | 信息整合、流程自动化 |
| Code | Claude Code, Codex | TuriX CUA, OpenClaw | agentic 执行、多步任务 |

**OPT/OPC 指挥链**：你（决策）→ Chat 顾问 → Cowork 总管 → Code 执行 → 你（验收）

**最小可行工具栈**：**Kimi + Hermes + Claude Code 三件套**覆盖 80% 场景。

### 1.9 ⭐ 龙虾 vs Hermes

**调试期用龙虾，生产期用马。**

| 维度 | OpenClaw（龙虾） | Hermes（马） |
|------|------------------|--------------|
| 定位 | 工具型 Agent | 智能体 |
| 演进 | 依赖人工 | **自演进** |
| 上手 | 中 | 高 |
| 场景 | 明确流程 | 探索性任务 |

Hermes 自动迭代 Skill：把使用过程的纠错动作自动写回 SKILL.md，类似 RLHF 但用编辑距离对比。

### 1.10 ⭐ Coze / Dify / N8N 对比

**Coze 和 Dify 互补，不替代。**

| 维度 | Coze | Dify | N8N |
|------|------|------|-----|
| 部署 | 云端优先 | 支持私有化 | 自部署 |
| 编程要求 | **低** | 中 | 中 |
| 定制化 | 受限 | 高度自由 | **最自由** |
| 节点丰富度 | 中 | 中 | **最丰富（10x Dify）** |
| 稳定性 | **高** | 需自行维护 | 需自行维护 |

**建议路径**：先 Coze 快速验证 → Dify/N8N 深度定制。复杂工作流推荐 **N8N**。

### 1.11 AI数据格式与知识库

- 推荐：结构化→JSON/YAML | 文档→**Markdown**（最AI友好）| 图形→Mermaid | 知识图谱→JSON-LD
- **不要用 PDF/Word 做知识库源——AI 读不准**
- 每篇一个主题、标题即摘要、用表格代替长段落、重要结论加粗

## ⚙️ 方向2：AI工作流搭建

### 2.1 AI编程最佳实践

**人做架构决策，AI 做实现执行。**

推荐工作流：Codex 架构设计 → Trae（Gemini）前端原型 → Claude Code 审查和深度实现。交接用 Markdown 标准化「交接文档」。

### 2.2 多Agent协同与人+AI团队

**人做决策，AI 做执行。**

- 每个 Agent 有明确角色（调研/文案/审核）
- 飞书文档或 Notion 做「共享看板」
- 每周一次人工复盘，从串行开始逐步并行

**Hermes + OpenClaw 多场景总控**：Hermes 拆解+分发，OpenClaw 各自干活。**Hermes ≠ 总控——它是工具不是角色，总控仍是你。**

### 2.3 ⭐ Coze/N8N工作流搭建与调试

**先跑通，再优化。**

- 调试：每次只改一个节点 | 用模拟输入测试 | 保留版本记录 | 复杂逻辑用子工作流
- Coze 不稳定通常是「提示词不够具体」
- 提示词越长越容易出错，拆分为多个简单 Agent
- **复杂计算别让 agent 算，让 agent 调 deterministic 函数**

### 2.4 业务场景AI工作流落地

**先跑人工版 3 次 → 再选工具 → 最后训龙虾。**

三步法：最小闭环（找高频痛点）→ 逐步扩展 → 人工把关

龙虾不读指定文件：在 CLAUDE.md 加"必须先 Read 指定路径才能开始任务"。**文件路径放第一句话——埋在中间会被忽略。**

### 2.5 上下文管理与Token优化

**根因：AI 不擅长自我总结和抽象。**

| 问题 | 根因 | 解决 |
|------|------|------|
| 对话越来越慢 | 上下文太长 | 定期开新对话 |
| AI 忘记早期要求 | 上下文漂移 | 开新对话先加载 MD |
| Token 爆炸 | 知识库太大 | RAG + 语义检索 |

**何时换对话框**：任务切换、上下文超 70%、AI 开始重复或混淆时。

**Obsidian 治理**：inbox 模式（`00-inbox/`）| 顶级分类 8-12 个封顶 | AI 只补元数据不移动文件 | 季度 rebuild 看分类漂移

### 2.6 Agent效果与模型选择

**模型决定上限，prompt/skill 决定下限。**

| 场景 | 推荐模型 |
|------|----------|
| 简单问答 | 国产免费模型 |
| 复杂推理 | Claude 3.5 / GPT-4o |
| 代码生成 | Claude Code |
| 中文内容 | Kimi / DeepSeek |

### 2.7 找技术人员落地工作流

**判断靠谱三信号**：
1. 能问清楚你的业务——不靠谱的人只问技术细节
2. 给得出 MVP 范围——不靠谱的人想"全包"
3. 愿意签验收标准——不靠谱的人"只对代码负责"

**最优路径**：自己学到能验收的程度 → 外包做 MVP → 自己维护和迭代

## 🏗️ 方向3：AI赋能具体场景

### 3.1 短视频与内容生产

**AI 是放大器，不是替代品。**

小红书爆款自动化：爆款采集（N8N+RSS）→ 结构拆解（Claude）→ 二创生成（模板+变量替换）→ 发布管理（Coze定时）

- 文案风格调教：别 fine-tune，喂 50 篇做 **few-shot prompt** 性价比高 10 倍
- 公众号自动编辑：Vercel / Cloudflare Workers（门槛低 10 倍）

### 3.2 数字员工与B端落地

**B 端核心壁垒是行业经验，不是技术。**

B端落地固定套路：
1. 选「人力密集 + 标准化程度高」的场景
2. 找最小闭环先跑通
3. ROI > 3 再扩展
4. 沉淀最佳实践

物流/供应链：先做单据处理（OCR+结构化）→ 异常预警 → 最后碰决策类

**AI 原生组织**：不是 token 消耗 > 人工，而是**人均产出由 AI 决定**——5 人公司一年产出过去 50 人的量。

### 3.3 方法论驱动的智能体

**把隐性经验显性化**——决策树 + 反例库 + 自我纠错。

YAI 的核心不是"知识库+工作流"：
- **决策树**：你在什么场景说什么、为什么
- **反例库**：哪些回答会被你否决、为什么否
- **自我纠错**：每次输出后跟标杆对比

Coze 知识库做不出来，是因为只有"对答库"没有"反例库"。

### 3.4 IP孵化与内容获客

**AI 做不好的事**：建立真实人际关系、深度共情、文化感知。

AI 赋能 IP 三层模型：

| 层级 | AI 作用 | 人的价值 |
|------|---------|----------|
| 选题 | 数据分析 | 洞察判断 |
| 内容 | 初稿生成 | 风格打磨 |
| 互动 | 数据统计 | 情感连接 |

**信息泄密风险**：Coze（云）> Claude/GPT（云但有企业协议）> **本地龙虾+本地模型（最安全）**

### 3.5 行业AI应用

- **可交 AI**：信息检索整理、标准化文档、数据清洗、初稿创作
- **必须人把关**：金钱决策、客户沟通关键节点、创意方向、法律合规

**核心心法**：AI 是加速器，不是自动驾驶。**人的判断力决定了 AI 产出的上限。**

AI 编程调 bug：让 AI **先解释 bug 再改**——「先告诉我根因，列 3 个假设，验证后再改」

## 💼 方向4：AI时代个人定位

### 4.1 个人能力进化

**不要问"AI 会不会替代我"，问"我的双三角缺哪个角，AI 能不能帮我补上"。**

- Skill 范式趋势：最终留下的是**提出问题的能力**
- AI 替代后人做什么：问题的提出者、价值的判断者、AI 协作的指挥官
- 教育孩子重点：**审美、沟通、内驱力**——AI 学不会

### 4.2 职业与教育变革

AI 对职业影响是**两极分化**：
- 被加速替代：标准化、重复性、有明确答案
- 变得更重要：创造性、复杂性、需要深度人际互动

**新手 0 到 AI 路径**：
1. 日常用 Kimi/豆包（建立习惯）
2. 学一堂课/Coze（搭第一个工作流）
3. 学 Claude Code（命令行+skill）
4. 训自己的龙虾（个人专属 agent）
5. **每一步都跑通一个具体业务再下一步**

### 4.3 教练与AI协作

人类教练护城河：**在场**和**信任**——AI 短期做不到。

AI 做「预习」和「复盘」，人主导「现场对话」。

### 4.4 行业个人转型

**用 AI 放大原有优势。**

两步法：1）盘点资产（行业经验、方法论、人脉）2）找放大点（哪个环节 AI 能放大 10 倍效率）

## ⚡ 方向5：学习路径和精力管理

### 5.1 学习心态与方法

**三板斧**：做减法、项目驱动、找到同伴。

| 情况 | 策略 |
|------|------|
| 现有工具能用 | **不换** |
| 新工具有明显优势 | 尝试验证 |
| 新工具只是微创新 | 等 6 个月 |
| 追新影响正常工作 | **放弃** |

**第一步**：选 Kimi/豆包 + Coze 开始，1 个月内不碰其他。

技术小白上手 CC/Codex：装 → 跑 5 个官方示例 → 写一个 skill → 用一个月解决一个真实业务。**别看课、要动手。**

### 5.2 知识管理与数据

- Obsidian 插件生态强但需配置 | IMA/GET 国产易用但生态弱 | 飞书协作方便但 AI 能力弱
- 先用飞书知识库，满足后再考虑 Obsidian
- 爬虫防封：官方 API > 付费数据源 > 低频爬取 > 高频绕过

### 5.3 AI产品商业化

**垂直 Agent 变现三条路**：
1. 卖订阅 SaaS
2. 卖咨询（按项目收费，B 端单价高）
3. 卖 Skill（marketplace 上架）

**个人最快路径**：先用 Agent 接咨询（验证价值）→ 稳定后再做 SaaS

**核心**：垂直 Agent 关键不是技术，而是**行业深度**。技术壁垒是暂时的，行业 Know-How 是长期的。

### 5.4 组织AI应用与安全

**企业 AI 落地三问**：值不值得？能不能用？怎么落地？

数据安全：敏感数据用私有化部署 | 飞书/钉钉企业版有更好隔离 | 定期审计 AI 输出准确性

**OPT 注意力/精力/自律**：
- 注意力被 AI 带跑：用 plan.md 锚定意图
- 精力周期：高能做创造，低能让 AI 自动跑
- 自律：给 AI 设定时报告（每 2h 进度），外部 deadline 倒逼

### 5.5 工具认知与选择

Claude Code vs OpenClaw 是**互补关系**：

| 对比 | Claude Code | OpenClaw（龙虾） |
|------|-------------|------------------|
| 本质 | Anthropic 官方 CLI | 基于 CC 的本地化产品 |
| 优势 | 最新功能最快 | 中文 UI、skill 市场、群聊、记忆系统 |

龙虾火的原因：中文社区 + skill 市场降低门槛 + Truman 产品节奏快

### 5.6 AI幻觉应对

| 方法 | 适用场景 | 成本 |
|------|----------|------|
| 人工审核 | 高价值输出 | 高 |
| 工具调用 | 事实性查询 | 中 |
| Prompt 约束 | 格式类输出 | 低 |
| RAG 检索 | 知识类内容 | 中 |
| 多模型交叉验证 | 重要决策 | 高 |

验证 AI 数据：让 AI 引用源 → grep 验证 → 关键决策双模型交叉验证

垂类模型：数据量 < 1 亿条，建议**微调 + RAG**，不从头训练。

## 📌 五大方向总结

| 方向 | 一句话总结 |
|------|-----------|
| 工具使用 | **不要系统学习，先解决一个真实问题。**选一个工具，做一个场景，跑通再说。 |
| 工作流搭建 | **工具不重要，场景和练习才重要。**从自己的场景里长出你自己的 Skill。 |
| 赋能场景 | **从真实数据里找场景，从第一个闭环开始。**脱敏优于换工具。 |
| 个人定位 | **从人生红点到双三角模型。**AI 做你的手，你做 AI 的脑。深耕 AI 做不到的——共情、直觉、信任。 |
| 学习路径 | **克服焦虑靠行动，不靠信息。**做减法、项目驱动、找到同伴。 |

## 🔑 十大金句

1. **人在环**：先 AI 辅助+人审核 → AI 主导+人抽查 → AI 自动+人只看结果。别跳级。
2. **显性化**：AI Agent 的"记忆"不是真正的记忆，而是上下文重载，需要通过 Skill、MD 文件显式传递状态。
3. **贵的便宜**：复杂任务用 Opus 一次到位反而比 Sonnet 反复迭代省。
4. **先跑3次**：没跑过 3 次人工版的工作流不要做成 Skill——会僵化。
5. **中央集权**：多 Agent 协同，中央集权比扁平群聊更稳定。
6. **调试期用龙虾，生产期用马**：OpenClaw 透明可调试，Hermes 自演进修长任务稳。
7. **行业深度 > 技术壁垒**：垂直 Agent 的关键不是技术，而是行业 Know-How。
8. **AI 是加速器，不是自动驾驶**：人的判断力决定了 AI 产出的上限。
9. **做减法**：选一个工具，做一个场景，跑通再说。
10. **提出问题 > 回答问题**：未来最稀缺的是知道自己要什么、知道自己缺什么、知道怎么补齐的人。
